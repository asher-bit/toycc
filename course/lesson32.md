## 1. 为什么单卡不够用

```
70B fp16 权重 ≈ 140 GB      H100 单卡显存 80 GB  ← 装不下
70B W4A16  ≈ 35 GB          但 KV cache(31课) 还要几十 GB
训练呢?  权重140 + 梯度140 + Adam 状态(m+v, fp32)280 ≈ 560 GB
         再加 fp32 master 权重副本(+280) ≈ 840 GB  ← 至少 8~11 卡
(混合精度训练 12~16 B/参数; 560 是不保留 master 副本的下限口径)
```

"装不下"的解法只有一条路：**把模型切开，分到多卡**。
怎么切，决定了通信量——而通信量决定"8 卡到底能不能当 8 卡用"。

## 2. 四种并行范式：切什么、通信什么

| 范式 | 切什么 | 每步通信 | 通信原语 |
|---|---|---|---|
| **DP** 数据并行 | 数据（每卡整模型，切 batch） | 梯度全量 | **allreduce** |
| **TP** 张量并行 | 权重矩阵（按行/列切） | 每层的中间激活 | allreduce / allgather |
| **PP** 流水线并行 | 层（前 L1 层卡1，后 L2 层卡2） | 层间激活 | send/recv（点对点） |
| **EP** 专家并行 | MoE 的专家（每卡几个专家） | token 路由 | **all-to-all** |

**一句话记忆**：DP 切数据、TP 切权重、PP 切层、EP 切专家。
真实大模型训练 = 它们的组合（如 DP×TP×PP 的"3D 并行"）。

### 2.1 TP 为什么通信最频繁

```
一层的一个 GEMM: Y = X·W, W 按列切成 [W1|W2] 两张卡:
  卡1: Y1 = X·W1     卡2: Y2 = X·W2     Y = [Y1|Y2]
下一层若按行切 W':  Y·W' = Y1·W1' + Y2·W2'  ← 两个部分和要相加!
→ 每层一次 allreduce(把两张卡的部分和加起来)
```

TP 每层通信一次，通信量 = 激活大小（batch×seq×d×2B）。
**TP 只敢在节点内做**：跨节点 IB 50GB/s 比 NVLink 900GB/s 慢 18 倍，
带宽撑不住——这是"TP 放节点内"的原因；而"TP≤8"来自单机 NVLink 域就是 8 卡。

### 2.2 PP 为什么通信最少但有"气泡"

PP 层间只传一次激活（点对点），通信量最小。但流水线要
"前一层算完下一层才能开始"——**流水线气泡**（bubble）：

```
手算: 4 卡 PP, 每段算 1 单位时间, batch 切成 m 个 micro-batch:
  总时间 = (m + 4 - 1) 单位   气泡 = (4-1)/(m+3)
  m=1: 气泡 75%   m=8: 气泡 27%   m=32: 气泡 8.6%
→ micro-batch 越多气泡越小, 但单步显存/调度开销涨
```

## 3. allreduce 的带宽模型（手算）

DP 的核心通信是 allreduce：**每卡都有梯度的一部分，要让每卡
都得到总和**。naive 做法（都发给卡0再广播）是 O(N·S)；
**ring allreduce** 做到与卡数几乎无关：

### 3.1 ring allreduce 手算

```
8 卡围成环, 梯度总量 S, 每卡只和左右邻居通信, 分两步:
  reduce-scatter: 每卡传 (N-1)/N × S 字节, 环走一圈, 每卡得到"总和的一段"
  allgather:      再传 (N-1)/N × S 字节, 每卡拿到全段

总流量/卡 = 2 × (N-1)/N × S ≈ 2S   ← 与卡数 N 无关!
```

```
手算: 70B 训练, 梯度 S = 140GB(fp16), 8 卡, NVLink 900GB/s:
  allreduce 时间 = 2 × 140GB × 7/8 / 900GB/s ≈ 272 ms
  注意: 这是"每卡摊到"的时间, 且 8 卡和 80 卡几乎一样(N-1/N≈1)
```

**结论**：ring allreduce 的可扩展性 = "加卡不加通信时间"
（在 NVLink 环内）——这就是 DP 能 scale 到几千卡的数学原因。
tree allreduce 是另一解：延迟 O(log N)。消息小时耗时由 logN 步的延迟主导，tree 更优；消息大时环的 2(N-1)/N×S 带宽占优。

### 3.2 通信原语速查

```
allreduce       全归约(每卡都得总和)      DP 梯度 / TP 层间
allgather       全收集(每卡都得全量)      ZeRO 参数收集
reduce-scatter  归约+分散(各得一段总和)   ZeRO 梯度分片 / TP
all-to-all      每卡给每卡发不同数据      MoE 专家路由(最贵)
send/recv       点对点                    PP 层间
```

## 4. 通信硬件的带宽层级（背这张表）

```
片内:  SM ↔ HBM            2~3.35 TB/s   (第15课)
节点内: NVLink(H100)       900 GB/s      TP 的家
节点间: InfiniBand/RDMA    400 Gb/s = 50 GB/s   ← 比 NVLink 慢 18 倍!
        GPUDirect RDMA: 网卡直读 GPU 显存, 不过 CPU
```

**分层决策**：TP（每层 allreduce）只敢放 NVLink 域内；
DP（每步一次 allreduce）可以跨节点（梯度桶重叠计算）；
PP（点对点，通信最少）天然适合跨节点。
**所以 3D 并行的标准摆法是：节点内 TP，节点间 PP+DP。**

## 5. 通信与计算重叠（编译器/系统视角）

stream/event 在分布式下的放大版：

1. **梯度分桶（bucketing）**：不等所有梯度算完，按层分桶，
   算完一桶就 allreduce 一桶（反向传播倒序出梯度，桶按序发）——
   通信藏在计算里。**桶大小是调度参数**（autotune 的对象）
2. **TP 的通信融合**：allreduce 拆成 reduce-scatter + allgather
   夹在下个 GEMM 里（计算通信重叠），这是 Megatron/编译器
   插入通信算子的标准做法
3. **编译器插入通信**：图 pass 识别"这一刀切了"→ 插入
   allreduce/allgather 节点——**通信算子是 IR 里的一等公民**，
   你写的编译器要会调度它（算子融合的通信版）

## 6. FAQ

**Q：EP 的 all-to-all 为什么最贵？**
A：别的原语每卡只和固定邻居/全体交互，all-to-all 是"每卡给
每卡发不同数据"——交换矩阵是满的。MoE 模型每层每个 token
都要路由到对应专家卡，消息流数量按专家数 N² 涨，字节量由 token×k 决定——EP 的规模
被 all-to-all 带宽直接卡死。

**Q：为什么训练用 DP+TP+PP，推理只用 TP？**
A：训练要同步梯度（DP 必需）；推理没有梯度，瓶颈是显存
（权重+KV）——TP 切权重/KV 刚好解决，且 TP 的通信（每层
allreduce 激活）在 NVLink 内可承受。推理也用 PP（层切分）
在超大模型，DP 在推理侧退化为"多副本负载均衡"。

**Q：scale 到几百卡，效率怎么估？**
A：通信/计算比：每层计算时间 vs 通信时间。batch 越大计算
占比越高（计算∝batch，通信∝激活∝batch 但 DP 通信∝参数——
不随 batch 涨！）所以 **大 batch 是 DP 效率的朋友**，
这也是"大模型训练追大 batch"的系统原因。

**Q：自研芯片要支持什么通信？**
A：至少：卡间直读（类 NVLink 的 P2P）、集合通信库（类 NCCL，
对 allreduce/allgather/reduce-scatter/all-to-all 有硬件加速或
高效软件实现）、GPUDirect RDMA（跨节点）。**检验标准：没有
P2P 直读，TP 每层通信就得走 PCIe，比 NVLink 慢一个量级以上**。

## 7. 本课小结

- 四种并行：DP 切数据（allreduce 梯度）、TP 切权重（每层通信）、
  PP 切层（点对点+气泡）、EP 切专家（all-to-all 最贵）
- ring allreduce：每卡 2(N-1)/N×S 字节，**时间几乎不随卡数涨**
- 带宽层级：HBM(3TB/s) ≫ NVLink(900GB/s) ≫ IB(50GB/s) →
  决定"TP 在节点内、PP/DP 跨节点"的摆法
- 通信藏进计算：梯度分桶、TP 通信融合——编译器插入通信算子
- 推理侧：TP 为主（切权重/KV），DP 退化为多副本

## 深层拓展：分布式的三个进阶问题

### A. ZeRO：把"每卡一份"再切一刀

DP 的浪费：每卡都存全量权重/梯度/优化器状态。ZeRO 把它们
**分片**（stage 1/2/3 分别切优化器/梯度/参数），用 allgather
在用时收集——显存省 N 倍，通信换显存。第 6 课内存规划的
分布式版：**显存永远是约束，通信是货币**。

### B. 为什么 MoE 是 all-to-all 的形状

MoE 每层：每 token 选 top-k 专家 → token 要发到专家所在卡 →
算完发回。交换矩阵 = 卡数×卡数。优化方向：专家放置（热门
专家多副本）、路由均衡 loss、all-to-all 与计算重叠——
这是 2025+ 大模型系统论文的富矿。

### C. 通信占比的 roofline 判断

```
加速比上限 = 计算时间 / (计算时间 + 通信时间)
TP=8 后还想加卡? 每层通信时间不变、每层计算被更多卡分小 → 通信占比只会涨
→ 这时候该换的是"切法"(加 PP 维度) 不是"加卡"
```
什么时候加卡不划算，和 19 课 roofline 是同一个判断框架：
找瓶颈资源，算它的时间占比。
