# GPU 第 11 章：浮点误差与数值验证——kernel 算得"对"是什么意思

## 1. 本章目标

- 能手算 fp32/fp16 的表示误差（ulp）与舍入方向；
- 能解释"求和顺序改变结果"（非结合性）并给出可控的写法；
- 能说出 Kahan 求和、混合精度 loss scaling 各解决什么问题；
- 能搭一套 kernel 数值验证协议（参考实现 + 误差阈值 + 边界输入），而不只是"看起来差不多"。

前置：第 18 课（量化误差）、第 2 课（参考执行器纪律）。本章全部手算，不需要 GPU。

## 2. 为什么"数值验证"是 kernel 工作的日常

kernel 优化的每一步都在重排计算顺序（融合、tile、流水），而**浮点加法不满足结合律**：

```text
(1e16 + 1) + 1 = 1e16          ← 1 被吞掉
1e16 + (1 + 1) = 1e16 + 2      ← 先加小的, 保留下来
```

所以"优化前后结果 bit 级一致"往往做不到，"误差在可接受范围"才是正确性的定义。**数值验证 = 把"对不对"变成可计算、可写进 CI 的阈值**。

## 3. 表示误差的手算：ulp 从哪来

**ulp（unit in the last place）**是"1.0 附近相邻两个可表示数的间隔"。手算两种格式：

```text
fp32: 尾数 23 位 → ulp(1.0) = 2^-23 ≈ 1.2e-7
fp16: 尾数 10 位 → ulp(1.0) = 2^-10 ≈ 9.8e-4
```

一个数的舍入误差最多半个 ulp（就近舍入）。直接推论：

```text
fp16 里 1.0 + 0.0001:  0.0001 < 半个 ulp(9.8e-4/2 ≈ 4.9e-4) → 被舍入吞掉
fp32 里同样加法:       远大于半个 ulp(6e-8) → 保留
```

**这就是"fp16 累加必须用 fp32 累加器"的第一原因**：fp16 的 ulp 太粗，逐次累加的每次舍入都会丢有效位；Tensor Core 的 mma 输出本来就是 fp32 累加，不是巧合。

## 4. 误差传播与求和顺序

### 4.1 朴素累加的顺序依赖

对 N 个数的顺序求和，误差按 O(N·ulp) 量级累积；更糟的是**大数吃小数**：

```text
手算: 1e8 个 1.0 顺序加到初值 1e8 上
  前 1e8 步: 每次 1e8 + 1 的尾数装不下那个 1 → 全部被吞
  结果: 仍是 1e8, 丢了 1e8 的累加量 → 相对误差 100%
```

### 4.2 两种可控写法

**成对求和（pairwise）**：把序列两两相加成树，误差降到 O(log N · ulp)——归约 kernel 的树形结构（第 23 课）天然就是 pairwise，比串行求和稳一个数量级。

**Kahan 求和**：每一步把"被舍掉的尾巴"记下来，下一步补回去：

```text
c = 0                       # 补偿项(上次丢的尾巴)
for x in xs:
    y = x - c               # 先把尾巴补进这次输入
    t = s + y               # 累加
    c = (t - s) - y         # 算出这次又被舍掉的量
    s = t
```

一句话：**Kahan 把"舍入误差"变成显式变量，随循环携带**——与 SSA 里"把循环携带值写成 phi/iter_args"是同一结构（第 1 章循环、MLIR 01 的 iter_args）。

## 5. 混合精度的误差管理

第 33 课的量化误差管的是"压缩表示"，本节的误差管的是"计算顺序"——两者在混合精度训练里汇合：

```text
fp16 前向:   激活/权重的 ulp 粗 → 梯度小值被吞
loss scaling: 把 loss 乘一个大系数(如 1024)再反传,
             让梯度落到 fp16 可表示范围, 反传完再除回去
fp32 master:  权重更新用 fp32 副本累积, 避免"小更新被大权重吞掉"
```

手算一个 loss scaling 的例子：真实梯度 1e-6，fp16 在 1.0 附近的 ulp 是 9.8e-4——**梯度直接被舍成 0**；loss ×1024 后梯度变 1.024e-3，落在可表示范围，训练才走得动。这就是"为什么 fp16 训练要 loss scaling"的完整推导。

## 6. kernel 数值验证协议（可写进 CI）

```text
① 参考实现: cuBLAS/PyTorch 高精度结果(fp32/fp64)当裁判(第 2 课纪律)
② 阈值按位宽定: fp16 kernel vs fp32 参考 → 相对误差 1e-2 量级
                fp32 kernel vs fp64 参考 → 相对误差 1e-5 量级
③ 输入集合: 常规分布 + 极端(全 0/全 NaN/最大最小/次正规) + 边界 shape
④ 逐层定位: 整网误差超限时, 按算子逐层二分(哪个算子的误差先爆)
⑤ 误差报告: max 相对误差 + 误差分布(p90/p99), 不是只看一个 mean
```

三条红线：**用 mean 误差当指标**（一个 outlier 就能掩盖）→ 报 max/p99；**只看一种输入**（边界输入最易翻车）→ 第 ③ 条的集合；**"看着差不多"当验收** → 阈值写进测试，用 FileCheck/pytest 钉住（第 3 章纪律）。

## 7. 常见错误与归因

| 现象 | 根因 | 修正 |
|---|---|---|
| 优化后误差突然变大 | 计算顺序改变 + 未设阈值就上线 | 先立阈值再改顺序 |
| fp16 训练不动/梯度全 0 | 小梯度被 ulp 吞掉 | loss scaling（第 5 节手算） |
| 归约结果不稳定 | 串行求和顺序依赖 | 树形归约 / Kahan |
| "误差 0.5" 这种报告 | 用了 mean 或只测一种输入 | max/p99 + 边界输入集 |
| 大数加小数丢精度 | 未对齐量级的直接相加 | 重排或换更高精度累加 |
