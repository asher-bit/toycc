# GPU 第 12 章：版本兼容与部署排查清单——"编译过了为什么跑不起来"

## 1. 本章目标

- 能画出"编译期 / 加载期 / 运行期"三个错误域的边界，并把手里的报错归到正确的一域；
- 能手算"某份 cubin 在哪些 GPU 上能跑"（第 2 章第 7 节规则的实战化）；
- 能按清单排查一台客户机器上的"跑不起来"，并定位到 driver / toolkit / 架构 / 库版本的哪一项；
- 能给自研芯片列出一份"版本矩阵"的最小结构。

前置：第 2 章（产物链与兼容性账）、第 6 章（module 加载与 sticky error）。本章是可执行清单，不是新概念——全部建立在前面章节的账上。

## 2. 三个错误域：先归域，再排查

```text
编译期(本机):  nvcc/编译器报错 → 源码或编译参数问题
加载期(目标机): cuModuleLoad 报错 → 架构/driver/库版本不匹配
运行期(目标机): 结果错/崩溃 → 数据、同步、环境差异
```

判断口诀：**报错发生在"哪个机器上的哪个阶段"**。同一个现象"no kernel image is available"（错误码 209）只在加载期出现；如果它出现在客户机器而不是你的编译机，问题的答案在"你编了什么架构 × 他有什么卡"，而不是源码。

## 3. 兼容性手算：这份 fatbin 在哪台机器能跑

规则回顾（第 2 章第 7 节）：**同 major 内向前兼容，跨 major 靠 PTX JIT**。手算三例：

```text
fatbin 只带 sm_86 cubin:
  sm_86/sm_89 GPU → 命中 ✓    sm_90 GPU → 报 209 ✗
fatbin 带 sm_86 cubin + compute_86 PTX:
  sm_90 GPU → cubin 不中 → JIT PTX → 能跑 ✓(首次加载慢, 有缓存)
fatbin 带 sm_70 cubin:
  sm_70 GPU ✓; sm_86 GPU? → 同 major(7 vs 8) 不同 → 不兼容 ✗
```

部署结论：**面向不确定的客户机器，fatbin 必须带 PTX**（JIT 兜底）；面向固定的自用集群，只带对应 sm 的 cubin（省体积、免 JIT）。这是"体积账 vs 覆盖范围"权衡的实战版（第 2 章第 7 节）。

## 4. 客户机器排查清单（按概率排序）

拿到一台"跑不起来"的机器，按这个顺序问：

```text
1. 显卡型号?           nvidia-smi → compute capability 是多少
2. driver 版本?        nvidia-smi 右上角(如 550.xx) → 支持到哪个 CUDA 版本
3. toolkit 版本?       nvcc --version → 编译用的 CUDA 是哪个
4. fatbin 里带了什么?  cuobjdump --dump-elf 看 sm 列表 → 有没有目标架构
5. 是不是 JIT 在兜底?  首次运行明显变慢 → 只带了 PTX
6. 库版本?             ldd 看 libcudart/libcublas 实际链接到哪个
7. 环境差异?           显存大小、GPU 数量、driver 里的其他进程占用
```

每项都对应一个课内账：1+2+4 决定"能不能加载"（第 2 章兼容性）；3 决定"编译参数对不对"；5 是 JIT 成本（第 2 章第 7 节）；7 是运行期资源（第 3 章 occupancy 的机器差异版）。

## 5. 版本矩阵：给自研芯片的最小结构

商用工具链必须有"什么版本支持什么"的矩阵，最小四列：

```text
| 组件版本 | 支持的硬件代际 | 支持的 driver | 已知不兼容 |
```

例如 NVIDIA 侧的三个事实（示例，以官方兼容表为准）：driver 向后兼容 toolkit（新 driver 跑旧 toolkit 编的 cubin）；toolkit 有最低 driver 版本要求（新版 toolkit 需要足够新的 driver）；cubin 兼容由 major 决定（第 3 节）。自研芯片矩阵的第一版应该回答：**编译器版本 → 目标 ISA 版本 → 模拟器版本 → runtime 版本**四者的两两兼容关系——这就是第 27 课"差分测试"与第 24 课"五步"之外的第六步：版本协议。

## 6. 常见错误与归因

| 现象 | 所属域 | 根因与排查 |
|---|---|---|
| 本机编译报错 | 编译期 | 源码/参数问题，与机器无关 |
| 客户机报 209 | 加载期 | fatbin 架构与显卡不匹配 → 第 3 节手算 + cuobjdump |
| 客户机首次运行极慢 | 加载期(JIT) | 只带了 PTX → 带对应 sm 的 cubin |
| 同代码两台机器结果不同 | 运行期 | 时钟/显存/并发差异 → 第 7 章六步协议重测 |
| driver 更新后报错 | 加载期 | toolkit 与 driver 版本关系被破坏 → 对照官方兼容表 |
