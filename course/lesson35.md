## 2. 结构化稀疏（2:4 sparsity）：硬件白送的 2 倍

**是什么**：NVIDIA Ampere 起支持"每 4 个权重保留 2 个"的结构化
稀疏——张量核直接吃稀疏格式，算力翻倍。

**什么账**：权重字节减半（带宽账）+ 跳过零计算（算力账）。
**为什么不火**：精度损失比量化难控，训练流程要改；业界更常用
"量化 + 剪枝"的组合。但**自研芯片要不要硬件支持稀疏**，
是架构评审的常客——判据：目标模型权重 ≥ 某量级，且 2:4 剪枝后
端到端精度损失 < 阈值，才值得为它做硬件稀疏支持。

**接着读**：NVIDIA sparse tensor core 文档；33 课的量化对比着看。

## 3. MoE（混合专家）：稀疏激活的"条件计算"

**是什么**：每层有几十个"专家"子网络，每个 token 只激活
其中 top-k 个（如 Mixtral：8 选 2）——参数量大涨但每 token
计算量不变。

**什么账**：
- 赚：**容量/计算解耦**——8×7B 的模型只要 13B 的计算
- 花：显存装全部专家（显存账）+ EP 的 all-to-all 通信（最贵的通信原语）+ 负载均衡（热门专家挤爆）

**编译器视角**：路由（top-k 选择）是动态形状算子。grouped GEMM
是 MoE kernel 的核心形态——不同专家收到不同数量的 token，
把各专家的 GEMM 打包成同一批执行。

**接着读**：Mixtral/Qwen-MoE 论文 + vLLM 的 MoE 实现。

## 4. 投机解码（speculative decoding）：用小模型"猜"

**是什么**：小草稿模型先一口气猜 k 个 token，大模型**一次前向
并行验证**——猜对几个赚几个。

**什么账**：decode 是带宽受限（瓶颈在"读权重"不在"算"），
所以"大模型一次验证 k 个"和"一次算 1 个"**读权重次数一样**——
多出来的算力是白捡的带宽空闲。接受率 ~70% 时吞吐 2~3 倍：
草稿一次猜 k 个、验证一次通过的比例为接受率 α，期望产出
≈ 1 + α + α² + …（α=0.7 时总量 ≈ 3.3 倍、净增 ≈ 2.3 倍）；
这是"验证开销可忽略"的理想账，实际还要扣掉草稿模型自身的开销。

**为什么不总是开**：prefill 是算力受限、带宽空闲（第 31 课手算 2），
而且它已把 N 个 token 并行算完——投机省不了权重读取次数；
batch 大时算力也没有富余。**判断框架还是 roofline**：带宽有空闲
才有投机空间。

**接着读**：Medusa/EAGLE 论文；vLLM 的 speculative 配置。

## 5. MLPerf 与基准：性能声明怎么被审计

**是什么**：MLPerf 是业界标准 benchmark（训练/推理两套），
厂商的"快 2 倍"都要在这里过审。

**什么账**：高性能部看任何性能数字先问四个问题：
```
1. batch 多大?        (decode 小 batch 带宽受限, 大 batch 算力受限)
2. 精度格式?          (fp16 还是 w4a16/fp8, 33 课)
3. 序列长度?          (KV cache 账, 31 课)
4. 含不含通信?        (多卡时, 32 课)
```
**四个变量没说全的性能数字，等于没说**。这也是 benchmark 方法论的会议室版。

**接着读**：MLPerf Inference 结果页（看 NV/AMD/各家的提交说明）。

## 6. 框架编译器接入点：你的活从哪进

**是什么**：PyTorch 的编译链 TorchDynamo（抓图）→ AOTAutograd
→ Inductor（图优化 + Triton 代码生成）。自研芯片进生态的路径：

```
路径 A(重, 一劳永逸):  替换 Inductor 的 codegen 后端 → 你的芯片
                      直接吃 PyTorch 模型(第 24 课五步的产品版)
路径 B(轻, 快速验证):  注册自定义算子库 → eager 模式先跑通
                      再逐步让编译链路接管
路径 C(平行生态):     ONNX → 你们的编译器(17 课前端) → 推理部署
```

**什么账**：接入成本 vs 生态覆盖——A 要 1~2 个工程师年
（3~5 人团队、覆盖全部算子）；B 两周起步（先覆盖你们急用的
几十个算子）；C 折中（覆盖 ONNX 算子集）。一条可行路线是 B→C→A。

**接着读**：Inductor 文档 + torch.compile 的 backend 注册接口。

## 8. 本课小结

- 结构化稀疏（2:4）：硬件白送 2 倍，但业界更爱量化+剪枝
- MoE：容量/计算解耦；代价是 all-to-all + 负载均衡 + grouped GEMM
- 投机解码：用带宽空闲换吞吐，roofline 判断什么时候值得
- MLPerf：性能数字四问（batch/精度/序列/通信）
- 进生态三路径：B（算子库）→ C（ONNX 平行）→ A（Inductor 后端）
- 主线闭环：从 toycc 的第一张计算图到高性能部的会议室
