# 第 33 课：生产级量化——W4A16、GPTQ/AWQ，以及"量化为什么是 kernel 问题"

> 本课风格：手算带宽账 + 误差账 + kernel 视角。
> 目的：int8 量化的数学原理已经讲过；本课补上生产现场：
> 为什么 LLM 用 W4A16 而不是 W8A8、误差怎么控、
> dequantize 为什么必须融进 GEMM。
> 前置：第 18 课（量化原理）、第 31 课（decode 带宽模型）、第 19 课（roofline）。

---

## 1. 从原理到生产：一句话的差距

前面你学会了：`scale = max|x|/127`、`误差 ≤ scale/2`、
int8 对称量化。但生产 LLM 部署的主角是 **W4A16**：
**权重 4bit、激活 16bit**。为什么不是 W8A8 全 8bit？

```
W8A8:  激活也量化 → 同代张量核 int8 吞吐是 fp16 的 2 倍, 计算受限场景可获 2× 算力
W4A16: 只有权重量化 → 显存/带宽省 4 倍, 计算仍是 fp16 张量核
```

decode 在小 batch 下是带宽受限（瓶颈在"读权重"不在"算"），
所以**省权重字节 = 直接省时间**，而激活量化的算力收益在
带宽瓶颈下毫无意义——这就是 W4A16 成为推理标配的逻辑。

---

## 2. W4A16 的账：速度几乎 = 位宽比

> **手算 1：70B 从 fp16 到 W4A16**
>
> ```
> fp16:  140 GB → A100 80GB(2TB/s) decode 上限 = 140/2000 = 70 ms/token ≈ 14 tok/s
> W4A16: 35 GB  → 35/2000 = 17.5 ms/token ≈ 57 tok/s   ← 接近 4 倍
> ```
>
> "接近"而不是"正好"4 倍：dequantize 有开销（4bit 解成 fp16 要算），
> 且激活/KV cache 读取没变。带宽收益 4 倍 × dequant 开销和
> 激活/KV 未压缩占比打折扣 → 真实收益 2.5~3.5 倍——**带宽受限场景，
> 量化收益 ≈ 位宽压缩比**，这条经验公式会议室里直接用。

> **手算 2：为什么 prefill 量化收益小**
>
> prefill 算力受限：瓶颈是 fp16 张量核的 312 TFLOPS，
> 不是带宽。W4A16 后计算还是 fp16（dequant 后）→ **prefill 几乎不提速**。
> 所以"量化让推理快 3 倍"这句话只在 decode/小 batch 成立——
> 高性能部里说这句话要附带前提，不然会被当场纠正。

## 3. 误差侧：为什么 A16 不能轻易降成 A8

outlier 会毁掉 scale。LLM 的**激活**恰好是
outlier 重灾区（某些通道的值是其他的 50~100 倍）：

```
手算: 某层激活 [-0.5 .. +0.5] 占 99.9%, 但一个 outlier = 48
  scale = 48/127 = 0.378  → 最坏误差 = scale/2 = 0.19, 即正常值最多损失 38%
  权重分布好(高斯-ish), 同样 int8 误差 <1%
→ 激活量化难、权重量化易 → W(低bit) A(高bit) 的分工由此而来
```

**对策四招**（生产量化算法就这四招的组合）：

| 方法 | 一句话思想 |
|---|---|
| **per-group** | 不给整行一个 scale，每 128 个权重一组各给 scale → outlier 只污染 128 格 |
| **GPTQ** | 逐层用校准数据，量化一个权重后**调整剩余权重补偿误差**（二阶近似） |
| **AWQ** | 找出"对输出影响大的 1% 权重通道"，**放大保护**它们（等价于给重要通道更小的量化步长） |
| **SmoothQuant** | 把激活的 outlier **除下来乘到权重上**（数学恒等变换），让激活变好量化 → W8A8 成为可能 |

```
per-group 的账: group=128, 每 128 权重多存 1 个 fp16 scale:
  组数 = 70亿 / 128 ≈ 5470 万组
  额外字节 = 5470万 × 2B ≈ 109 MB ≈ 0.1 GB   (35GB 上的 ~0.3%)
  换来: 误差按组内 max 算, 不再被全局 outlier 拖死
```

## 4. kernel 视角：dequantize 必须融进 GEMM

W4A16 的 GEMM 长这样：

```
for 每个输出块:
  load int4 权重块          ← 带宽省了 4 倍, 这是收益
  dequant: int4 → fp16      ← 在寄存器里做, 不落显存
  fp16 张量核乘加            ← 算力没变
```

**关键工程点**：dequant 在寄存器/共享内存里完成——如果先
dequant 成 fp16 写回显存再读，带宽收益直接归零（还倒贴一次写）。
所以 **W4A16 的全部收益押在"dequant 融合进 GEMM 的 prologue"**——
这就是标题里"量化是 kernel 问题"的原因。

```
反面教材手算: dequant 落显存的 W4A16 GEMM
  读 int4 35GB + 写 fp16 140GB + 读 fp16 140GB = 315 GB > 140 GB
  → 比不量化还慢 2 倍。融合 vs 不融合, 差 9 倍流量
```

**反直觉案例**：batch×序列长度大到算术强度越过 roofline 拐点时，
decode 变 compute-bound，W4A16 的 dequant 开销是纯增——**量化 kernel
反而比 fp16 慢**。
所以推理框架按 batch/shape 分发"量化 kernel 还是 fp16 kernel"——
动态形状分发的又一个实例。

## 5. 编译器接入点

1. **IR 层**：量化信息是元数据（per-group scale/zero_point 挂在
   权重上），legalize 时决定"融进 GEMM 还是独立 dequant 算子"
2. **调度层**：group size（64/128/256）是 autotune 的搜索维度——
   小组误差小但 scale 存储/解压开销大
3. **kernel 层**：int4 的解包（一个 byte 装 2 个权重）、
   位运算 dequant、与张量核的对接——自研芯片 ISA 要不要加
   "硬件 dequant 指令"是真实的架构决策
4. **校准层**：GPTQ/AWQ 在校准数据上跑前向——这是训练框架
   与编译器的接缝（导出量化参数 → 编译器消费）

## 6. FAQ

**Q：W4A16 vs W8A8 怎么选？**
A：看瓶颈：decode/小 batch（带宽受限）→ W4A16；大 batch/prefill
重（算力受限）→ W8A8（整数算力翻倍才有意义）。SmoothQuant
让 W8A8 的激活量化可用——所以"W4A16 推理 + W8A8 大吞吐 serving"
是 2025+ 的常见组合。

**Q：KV cache 也能量化吗？**
A：能，而且是显存大户（KV 可达权重的 5 倍）。
KV 从 fp16 降到 int8/fp8 只省一半：67GB → 33.5GB；若 KV 用 int4 才到 17GB——注意力对 KV 精度相对不敏感，
这是 serving 系统的标配优化。误差账一样：per-group scale。

**Q：FP8 是什么位置？**
A：H100 起硬件支持 FP8（E4M3/E5M2 两种格式），算力翻倍、
带宽减半——训练和推理都在切。E4M3（4 指数 3 尾数）给前向
权重/激活，E5M2（5 指数 2 尾数）给梯度（范围优先）。
它是"硬件原生量化"——不再是 int 模拟，是张量核直接吃 8bit 浮点。

**Q：什么时候不该量化？**
A：① prefill 主导的长 prompt 场景（算力受限，无带宽收益）；
② 模型已经很小（2B 以下）且 batch 大；③ 精度敏感任务
（数学/代码）上 4bit 的误差不值得省那点显存。

## 7. 本课小结

- W4A16 = 权重 4bit + 激活 fp16；**收益 ≈ 位宽压缩比**（带宽受限时）
- 激活 outlier 决定"A 难量化、W 易量化"的分工；
  per-group / GPTQ / AWQ / SmoothQuant 是误差控制的四招
- dequant **必须融进 GEMM**（寄存器里解压），落显存 = 收益归零
- 大 batch 下量化可能反而变慢——按 shape 分发 kernel
- FP8 是硬件原生 8bit 浮点，训练推理通吃的下一代

## 深层拓展：量化的三个进阶问题

### A. W4A16 的 GEMM 为什么不直接用 int4 张量核

有的芯片有 int8/int4 整数张量核（算力更高）——为什么不用？
因为**激活是 fp16**，混合精度 GEMM 需要整数权重 × 浮点激活，
原生整数核不支持。新架构在加"混合精度核"——这又是
"硬件跟着 workload 走"的例子（和第 21 课张量核同源）。

### B. 量化误差的端到端验证

量化模型的验收不是"单层误差"，是**端到端指标**（perplexity/
下游任务精度）。流程：量化 → 校准集前向 → 对比 perplexity
涨幅（<0.5% 可接受）→ 端到端 benchmark。这和第 2 课
"参考执行器 + max|Δ|" 是同一个方法论的产品版。

### C. 自研芯片的量化支持清单

```
1. int8/int4 解包与 dequant 指令(或在 kernel 里位运算)
2. FP8 张量核(E4M3/E5M2) 或混合精度核
3. per-group scale 的数据布局(和权重交错存放, 一次缓存行全拿到)
4. 编译器: 量化元数据进 IR → dequant 融合 pass → group size autotune
```
第 3 条是容易翻车的细节：scale 若和权重分开放，
dequant 时要多读一次显存——**数据布局设计直接吃掉量化收益**。
